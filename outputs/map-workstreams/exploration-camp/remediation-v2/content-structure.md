# `/join` 内容结构

状态：`APPROVED_IMPLEMENTATION_INPUT / NOT_RENDERED`

## 阅读顺序

定向块由 Server Component 渲染，位于页面现有 H1 之后、错误提示和邀请表单之前。这样真实
`/join#token=…` 首次 HTML 与 hydration 过程都不会出现“只有通行证、没有五地图”的空窗。

```text
现有品牌/通行证标题
→ 五地图定向块（无交互）
→ 当前错误（如有）
→ 当前邀请验证或身份确认表单
→ 唯一主操作
```

定向块不得包含 `a`、`button`、`input`、`form`、tab stop、未来地图入口或可点击地图节点。

## 固定文案

- Eyebrow：`Muchen Journey · 01 / 05`
- 标题：`五张地图，从探索营出发`
- 说明：`这是一段由五张地图组成的长期成长旅程。你现在从第 1 张地图「探索营」开始。`
- 事实 1：`全程 · 5 张地图`
- 事实 2：`当前位置 · 探索营`

不列出另外四张地图名称，避免在 `/join` 建立第二份五地图目录或可导航事实源。完整地图目录继续由
共享首页所有；本块只提供当前黄金路径的人类验收所需的三个事实。

## 阶段文案

| Phase | “现在” | “随后” | 页面唯一主操作 |
| --- | --- | --- | --- |
| `VERIFY_INVITE` | 验证专属邀请 | 进入探索营并打开第一份必读材料 | `验证专属邀请` |
| `CONFIRM_IDENTITY` | 确认这是你的邀请并开启旅程 | 在探索营打开第一份必读材料 | `开启旅程` |
| `REENTRY` | 确认邀请并恢复原有旅程 | 继续系统显示的当前动作 | `继续旅程` |

阶段文案放在稳定 DOM id（建议 `join-whole-journey-next-action`）内。邀请交换表单和身份确认表单
均通过 `aria-describedby` 引用该 id，使屏幕阅读器在操作按钮前获得同一真实上下文。

## 错误与等待

- 无 fragment：保留完整链接粘贴输入；定向块仍显示；主操作仍只有“验证专属邀请”。
- token 已读取：保留“专属邀请已安全读取，等待验证”；不回显 token。
- pending：按钮原位 disabled 并变为“正在验证/正在开启/正在恢复”；不得添加 spinner 按钮。
- 无效、过期、撤销、限流：错误提示位于定向块之后；恢复仍使用现有唯一表单主操作。
- re-entry：不得出现“新人”“重新开始”或“打开第一份材料”的虚假下一步；必须明确恢复原有进度。
