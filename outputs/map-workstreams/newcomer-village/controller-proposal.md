# 新手村总控集成提案

状态：`PROPOSAL_ONLY`；本地图未修改共享运行时、领域模型、API、设计系统、导航或发布配置。

## 学员需要

未来集成时，新人需要在新手村入口读取由共享平台提供的探索营成长基线与岗位/组织上下文，明确每个字段的来源、有效状态与真人门槛；完成真实融入行动后，证据草稿需要进入总控所有的 Evidence Ledger，由授权人与人工复核共同决定是否形成角色准备度或协作习惯证据。

## 建议的总控能力

1. 提供一个只读 `newcomer-context-snapshot` 投影，组合权威 `person-growth-baseline` 与岗位/组织上下文，并携带来源版本、授权范围、缺失状态和探索营真人门槛；地图不得缓存为第二事实源。
2. 在现有 Evidence Ledger 上定义受权的“新手村真实融入行动”证据写入合同。最小载荷为行动类型、协作角色（非姓名）、观察到的期待或习惯、下一次重复行为、学员自述标记和来源引用。
3. 由总控分配隔离运行时入口与跨地图转场；新手村不修改 `/` 或全局五地图导航。
4. 所有写入都需身份、最小权限、目的限制、人工复核与审计；不得从单条草稿自动产生录用、晋升、淘汰、薪酬、绩效或胜任结论。

## 兼容性与迁移

- 建议为加法式只读投影和证据类型扩展，不改变既有 Person、Capability、Progress、Identity 或探索营事实。
- 不迁移、不回填、不改写既有探索营基线或历史证据；合成 fixture 不得进入共享平台。
- 若 Evidence Ledger 当前不支持来源状态或学员自述标记，由总控先判断能否使用现有元数据；只有受影响地图的合同测试证明需要时才扩展共享 schema。
- 初次集成应受 feature flag 与独立候选清单控制，可回退到不暴露新手村入口的状态，不影响冻结中的探索营候选。

## 支持证据

`browser-evidence/` 证明了读取上下文、选择真实行动、形成最小证据草稿的体验需求，以及 390/768/1280 的布局边界；它不证明共享接口、权限、真人有效性或发布准备度。总控集成前仍需以契约 fixture 替换测试读取适配器，并独立验证身份、授权、审计和跨地图连续性。
