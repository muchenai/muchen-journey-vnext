## 3. 逐项裁决卡

### CON-001｜四个宝藏还是五个宝藏

- 证据：探索营 V1.0 正式链接目录为四个宝藏；V0.7增加“个人成长基线”。
- 第一性问题：第五项是业务必须经过的一站，还是评测后形成的数据结果？
- 推荐：保留四个宝藏；个人成长基线作为四宝藏后的结果包或下一步建议。
- 不推荐：为迁就现有页面或V0.7，直接把五项做成五站。
- 决策：`[x] V1.0四宝藏；个人成长基线作为结果包`
- 若另案，必须写明：第五宝藏 Owner、用户行为、输入、产出、人工 Gate、正式来源。

### CON-002｜人工流程还是全自助八站

- 证据：V1.0要求认知与实操；V1.1允许录播、题库、AI初评，但保留风险复核和最终名单确认。
- 第一性问题：哪些动作可以自动化，哪些判断必须有人负责？
- 推荐：内容学习和低风险练习可异步；实操提交、边界题、异常答案和最终结果保留人工 Gate。
- 禁止：点击材料、自填一条线索或“我已完成”直接改变正式状态。
- 决策：`[x] 学习内容可异步；正式能力结果来自实操、证据和人工Gate`

### CON-003｜是否允许真实项目任务

- 已定方向：允许。
- 生效前必须补齐六项：任务授权人、数据等级、脱敏方式、可见范围、Reviewer、保留期限。
- 建议的产品分区：
  - `通用学习/模拟任务`：可复用、低风险；
  - `受控真实项目任务`：逐项授权、限定参与人、人工审核；
  - `生产系统作业`：不在 Journey 内直接执行，通过受控接口回传结果证据。
- 当前状态：`IMPLEMENTATION_PENDING`。
- Gate：用一条真实任务完成授权—领取—提交—审核—返工—通过—归档演练。

### CON-004｜审核返工还是自证完成

- 已定方向：正式任务必须审核返工。
- 自证的允许用途：草稿保存、自查清单、提交前确认。
- 自证的禁止用途：产生 `Passed`、积分、能力证据或下一阶段准入。
- 当前状态：`IMPLEMENTATION_PENDING`。
- Gate：系统拒绝无Reviewer的正式通过，并保留每次提交与返工版本。

### CON-005｜2.0是否继续定义产品

- 已定方向：不允许。
- 保留：服务器、数据库、身份、任务、提交、审核、审计、发布、恢复、监控和通用UI组件。
- 暂停：没有 MAP-ID 的页面、业务状态、旅程、任务类型和内容扩写。
- 当前状态：`IMPLEMENTATION_PENDING`；代码基线收口尚未完成。
- Gate：PR 模板强制填写 MAP-ID、权威来源、Owner和真人验收。

### CON-006｜积分能否决定人才结论

- 新手村证据：积分来自真实贡献，并参与阶段评分和机会分配。
- V0.7治理：游戏账本与能力证据账本隔离。
- 推荐：积分可以影响激励和资源兑换；分流时只能作为一项可解释信号，必须与任务质量、Reviewer证据和人工判断组合。
- 禁止：按积分阈值自动淘汰、准入、晋升或赋予能力等级。
- 决策：`[x] 积分用于激励与参考，不能单独产生人才结论`

### CON-007｜探索营是否可以筛选

- V1.0证据：Day 1 是进入后续项目规则培训前的基础能力准入。
- V0.7候选：探索营为低压力入口，核心不淘汰。
- 推荐：Day 1 输出“进入下一训练阶段 / 补强后复测 / 暂缓”，不输出录用、淘汰或真实项目准入。
- 这样保留 V1.0 真实业务目的，同时防止一次自动测试变成人事终判。
- 决策：`[x] Day 1只决定下一训练阶段，不作录用、淘汰或项目准入终判`

### CON-008｜历史数据如何处理

- 当前事实：新手村被陈述为正式开放使用过，但尚未取得使用记录对账。
- 推荐顺序：备份 → 盘点 → 字段语义映射 → 数量对账 → 抽样核验 → 决定迁移/封存/不导入。
- 禁止：为了适配2.0 schema静默修改旧结论，或直接在线连旧库边跑边改。
- 决策：`[x] 先审计，再按证据分类为迁移、只读封存或不导入`

### CON-009｜第一发布是否包含全生命周期平台

- 证据：V0.7提出全员成长平台；刘默文裁决第一发布需要扩展 AI学院、公会、认证竞技场和 Career Map。
- 裁决：四个模块进入第一发布范围。
- 施工边界：纳入范围不等于无边界全量建设；每个模块必须分别明确用户任务、权威来源、Owner、最小闭环、MAP-ID、Build Contract和真人验收 Gate。
- 机会成本：第一发布范围扩大，会增加产品证据、内容、权限、数据和真人验收工作量；Release Owner必须在排期中显式反映，不能压缩探索营和新手村继承质量来换范围。
- 决策：`[x] 第一发布纳入AI学院、公会、认证竞技场和Career Map`

### CON-010｜AI评分与真人责任

- 证据：V1.1允许AI初评，V0.7要求高影响结论真人签署。
- 推荐：AI结果状态统一标记为 `AI_CHECKED`，只有授权 Reviewer 可转为 `FINALIZED`。
- 申诉：最终结论必须保留来源、Rubric、模型/Prompt版本、Reviewer和复核入口。
- 决策：`[x] AI只做自查、初评和摘要；高影响结论由真人签署并允许申诉`

## 4. 已批准的组合方案

业务 Decider 已于 2026-08-23 批准以下组合：

1. 探索营采用 V1.0 四宝藏；个人成长基线作为结果包。
2. 学习内容可异步，正式能力结果必须来自实操、证据和人工 Gate。
3. 允许受控真实项目任务，但不在 Journey 内直接执行生产作业。
4. 正式任务必须经过提交、审核、返工/通过；自证不产生正式状态。
5. 积分用于激励与参考，不能单独产生人才结论。
6. Day 1 决定下一训练阶段，不直接作录用、淘汰或项目准入终判。
7. 历史数据先审计再分类处理。
8. 第一发布需要扩展 AI学院、公会、认证竞技场和 Career Map；每个模块分别设置范围和 Gate。
9. AI只做自查、初评和摘要，高影响结论由真人签署并允许申诉。

状态处理：CON-001、002、006、007、009、010 标为 `DECIDED`；CON-003、004、005、008 标为 `IMPLEMENTATION_PENDING`。产品冲突已裁决，但恢复开发仍受证据、技术基线和 Build Contract Gate 约束。
