## 1. 建设目标

在 2026-09-01 前交付一个最多 25 人使用的 Muchen Journey 受控版本，使学员可以在同一产品中完成：

1. 探索营：四宝藏认知、三项能力实操、人工评审和个人成长基线结果包；
2. 新手村：受控真实任务或模拟任务的领取、提交、审核、返工/通过及下一任务；
3. AI学院：异步学习、结构化练习、人工点评、能力证据和组织资产候选；
4. 交付线公会：围绕交付通用能力完成短周期共同实践、导师反馈和下一步建议。

本次成功标准不是“页面齐全”，而是四个模块各至少跑通一条真实、可复核、可返工的用户闭环。

```text
沐晨新手村已验证的任务闭环
＋探索营 V1.0 的真实业务方案
＋V0.7 中经过批准的治理升级
＝Muchen Journey 产品行为基线

```

禁止两个反向替代：不能用旧表结构替代新领域设计；不能用现有代码/页面替代产品行为基线。

## 5. 最小跨模块旅程

```text
私密邀请/身份确认
  → 统一首页看见“今天只做什么”
  → 进入一个模块
  → 查看目标、边界、产物、Rubric、Reviewer、求助路径
  → 学习/练习/受控任务
  → AI自查（可选且标记）
  → 正式提交固定版本
  → 真人审核
  → 返工并重新提交 / 通过
  → 结果包与下一行动
  → 申诉或进入下一阶段
```

学员首屏必须回答：现在做什么、为什么做、交付什么、谁审核、何时完成、卡住找谁。不得首先展示面向开发者的 stage、hash、Gate 编号和元数据。

## 9. 代码变更规则

每个 PR/changeset 必须声明：

- `requirement_ids`；
- `source_refs`；
- `product_behavior_changed`；
- `schema_changed`；
- `security_or_data_scope_changed`；
- `tests` 与 `negative_tests`；
- `human_uat_required`；
- `rollback`。

没有来源 ID 的新业务状态、自动判断、地图、课程或字段必须失败关闭。当前 Mini 工作树不得被覆盖、清空或整分支盲合；先逐文件登记为 `KEEP / ADAPT / ARCHIVE / DROP`。

## 10. 发布总 Gate

只有以下全部满足才可进入明确发布决定：

1. 候选工作树干净，完整 Git SHA 和工件 hash 固定；
2. 四模块 P0 requirements 全部 PASS；
3. 空库迁移、升级、备份、隔离恢复和应用回滚通过；
4. 权限负向测试、生产写隔离、AI越权和积分越权测试通过；
5. 四模块各至少 2 名真实目标用户在生产基础设施的8人白名单Canary中完成同SHA UAT；
6. 业务 Owner 对内容和结果签署；
7. 冯宇汀完成独立 QA 和独立 Release Review；
8. 屠元琦完成 UAT 运营收口；
9. 刘默文先对固定候选显式签署 `CANARY_DEPLOYMENT_GO`，UAT和独立复核通过后再签署独立的 `RELEASE_GO`；
10. 小名单≤25、停邀请开关、告警人、回滚负责人和观察窗口已就绪。

任何 Gate 失败，结论只能是 `NO_GO` 或模块降级，不能由“9/1必须上线”自动改写为 PASS。
