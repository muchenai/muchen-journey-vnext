# 模块分册 02｜沐晨新手村

> 新手村运营 Owner：屠元琦  
> 产品继承重点：继承已验证任务闭环，不照搬旧23表结构或历史人才结论。  
> 真实任务边界：允许受控真实项目任务；Journey 不直接执行生产作业。

## 1. 使用者结果

学员在清楚目标、边界、Reviewer和求助路径的前提下，完成一项真实业务可使用或高保真模拟的产出，经真人审核返工/通过后留下贡献证据并进入下一任务。运营能管理任务发布、Reviewer容量、SLA、异常、积分来源和下一安排。

## 2. 必须继承的已验证闭环

```text
任务卡发布/触发
→ 学员领取并看清交付物和完成标准
→ 完成任务并提交交付物
→ NPC/Reviewer审核
→ 返工（不计正式完成）/通过
→ 形成贡献事实
→ 可产生积分/徽章（独立账本）
→ 下一任务/主线解锁
```

不可继承为正式结论的旧逻辑：积分直接分流、高潜自动名单、晋级/淘汰自动依据、未审核自证、点击完成。

## 3. 任务类型

- 主线任务：批次规定的共同底座，完成后才解锁依赖任务；
- 支线任务：学员按兴趣和发展方向选择；
- 隐藏任务：由真人发现有价值行为后补发或确认，不由系统秘密画像自动触发；
- NPC任务：明确任务发布/审核人；
- 受控真实任务：继承六项安全前置，生产动作在Journey外执行。

第一发布不需要把旧任务库全部上线。只需选择 1—3 条能跑通闭环的首批任务；旧“PM影子观察、质量观察员、风险雷达、Agent发现者、经营感知者”等作为候选，由屠元琦逐条批准。

## 4. 标准任务卡

| 字段组 | 必填字段 |
| --- | --- |
| 身份 | taskKey、moduleKey、TaskVersion、任务类型、主/支/隐藏 |
| 意义 | 为什么做、目标、非目标、对业务的价值 |
| 输入 | 材料、来源、版本、数据等级、前置条件 |
| 交付 | 交付物格式、示例/反例、截止时间 |
| 质量 | RubricVersion、通过标准、不可接受项 |
| 责任 | 授权人、触发NPC、Reviewer、替补、SLA |
| 安全 | 可见范围、脱敏、生产系统边界、保留期 |
| 支持 | 求助路径、升级条件、FAQ |
| 激励 | 基础积分、额外积分条件、重复规则（不影响能力结论） |

学员提交模板至少包含：完成了什么、关键发现、证据/交付物、遇到的问题、向谁请教、业务价值、不确定事项、AI使用披露。

## 5. 受控真实任务

发布前六项硬前置：授权人与用途、数据等级、脱敏方式、参与人与可见范围、Reviewer与替补、保留/删除规则。另须明确 Journey 外的生产执行人和系统。

Journey可以：展示脱敏输入、接收产物/最小证据、人工审核、记录结果、通知下一行动。

Journey不得：保存生产写凭证、自动向客户/生产系统发送、代表学员执行排班/交付/验收/工时、把未审核产物投递生产。

## 6. NPC/Reviewer运营

NPC不是全程老师，而是任务触发、背景补充、成果审核、反馈和积分确认者。每名Reviewer配置：专业范围、可见范围、每周容量、开放时段、首响SLA、完成SLA、替补和升级人。

超载/超时处理：停止新分配 → 通知运营 → 分配替补 → 保留原责任和时间线。禁止运营直接代评审关闭队列。

## 7. 积分与徽章

积分只奖励可验证贡献：提交交付物、人工通过、对真实业务有帮助、形成可复用资产。单纯参会、泛泛心得、刷低难度任务、无证据自述不计分。

首发允许：追加积分分录、累计/可用余额、来源链接、人工更正、简单徽章。延期：兑换商城、复杂排行、按积分自动解锁高影响机会。

## 8. 历史数据策略

- 旧新手村数据仅用于理解任务类型、字段、运营节奏和典型案例；
- 不要求23张表完整、不建立正式Legacy Snapshot、不迁移历史人员结论；
- `migrate_record_count=0`；
- 旧源文件/审计证据不删除；
- Journey2.0开发/测试库可在确认环境、备份和无生产影响后重置；
- 首发用新批次、新任务版本、新账号产生新事实。

## 10. 验收

- 一条任务走通领取—提交—审核—返工—再提交—通过；
- 所有历史版本和Reviewer理由可追溯；
- 真实任务能回答谁授权、谁可见、谁审核、数据在哪里、保留多久；
- Journey 无生产写凭证或直接生产 mutation 路径；
- 3/3学员能复述目标、交付、边界、Reviewer和求助；
- 运营能发现逾期、超载、通知失败并切换替补；
- 积分不能改变Evaluation、Evidence或正式结果。
