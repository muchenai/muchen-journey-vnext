# 模块分册 03｜AI学院

> AI学院 Owner：段超群  
> 定位：Muchen Journey 下的并列一级空间；飞书负责触达/讨论/共创，Journey负责路径、提交、沉淀、证据和看板。
> 正式方案：飞书 Wiki `GzknwrxybiOAOGkRrKKcjZyqnPb`（解析到《AI学院主管_2026下半年执行计划_V0.2》）。

## 1. 使用者结果

学习者完成一个学习单元后，不只“看过内容”，而是提交一份可复核练习，经真人点评返工/通过后形成能力证据；优秀成果可申请成为带 Owner、版本、适用场景和复用条件的组织资产。

## 2. 首发最小单元

```text
学习目标与适用条件
→ 异步内容链接/材料
→ 示例与反例
→ 结构化练习
→ AI自查（可选）
→ 正式提交
→ 真人点评
→ 返工/通过
→ 能力证据
→ 下一练习 / 组织资产候选
```

每个单元必须有：目标能力、适用角色、前置、来源、ContentVersion、预计时间、练习、交付格式、RubricVersion、Reviewer、有效期、下一行动。

## 3. 系统与飞书分工

| 飞书 | Journey |
| --- | --- |
| 全员/试点通知、直播、讨论答疑、每周提醒、月度点评摘要 | 学习路径、资料链接、任务、提交、版本、证据、Reviewer队列、进度/质量看板、组织资产 |

飞书群消息或直播签到不能替代 Journey 的正式提交与证据；Journey也不复制所有讨论内容。

## 4. 学习、练习、证据与资产

- `LearningMaterialCompletion`：只记录材料行为；
- `PracticeEvidence`：练习提交事实；
- `HumanEvaluationEvidence`：真人按Rubric点评；
- `OrganizationAssetCandidate`：通过后经内容Owner批准的复用候选；
- `OrganizationAsset`：补齐来源、Owner、版本、许可/敏感度、适用场景、复用条件后发布。

资产入库不会自动证明作者具备岗位等级；复用次数也不自动形成高潜结论。

## 5. AI自助辅导包

允许包含：任务拆解Prompt、结构检查、事实核验提醒、反例对照、表达优化和敏感信息检查。必须清楚提示不提供直接答案、不替代学员产出、不替代Reviewer。学员提交时披露AI使用范围。

## 6. 运营节奏

首发只需跑通一个单元，保持后续节奏接口：

- 月初：发布主题、课程、练习、AI自查包和截止时间；
- 每周：查看聚合进度、延期和链接有效性；
- 截止前：系统/飞书提醒；
- 月末：真人评价、证据卡、组织资产候选和共性问题；
- 下一周期：引用已批准资产和修订内容版本。

## 7. 看板

- 应完成人数、已提交、已通过、返工、延期、未提交；
- 首次提交到首次反馈时长；
- 返工后通过率；
- Reviewer一致性；
- 组织资产候选/已入库/复用次数；
- 30天内证据被下一任务引用情况。

观看完成率只作过程诊断。

## 9. 验收

- 3/3学习者无需讲解完成练习并说出适用任务；
- 阅读、自测、AI初评、提交、人工结论可区分；
- 至少一次返工闭环；
- 2名Reviewer完成同一校准样例；
- 一个优秀产出走到组织资产候选，但未经Content Owner不能发布；
- 系统不能基于完成率/AI评分自动认证、高潜或岗位适配。
