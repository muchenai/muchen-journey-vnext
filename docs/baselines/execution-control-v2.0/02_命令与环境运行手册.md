# 命令与环境运行手册

本手册中的命令均在 Mini 本机执行。先运行 `scripts/v2_preflight.py`；不得直接跳到构建或候选冻结。

## 1. 固定工具与隔离变量

```bash
export PATH="/usr/local/bin:/Applications/ChatGPT.app/Contents/Resources/cua_node/bin:$PATH"
MJ_V2_REPO="/Users/liumowen/Documents/Muchen Journey2.0-candidate-prep-20260826"
MJ_V2_PROJECT="muchen-journey-v2-candidate"
MJ_V2_DB_PORT="35442"
MJ_V2_API_PORT="38010"
MJ_V2_WEB_PORT="33010"
MJ_V2_EVIDENCE_ROOT="/Users/liumowen/Documents/Muchen Journey2.0-evidence/final-candidate-v2"
cd "$MJ_V2_REPO"
```

不得停止、删除或复用当前 `journey-next-*` 容器。所有 `docker compose` 命令必须显式带：

```bash
COMPOSE_PROJECT_NAME="$MJ_V2_PROJECT" \
MJ_DB_PORT="$MJ_V2_DB_PORT" \
MJ_API_PORT="$MJ_V2_API_PORT" \
MJ_WEB_PORT="$MJ_V2_WEB_PORT"
```

## 2. V2 起跑校验

```bash
python3 docs/baselines/execution-control-v2.0/scripts/v2_preflight.py --repo "$MJ_V2_REPO"
cd docs/baselines/execution-control-v2.0
shasum -a 256 -c SHA256SUMS
cd "$MJ_V2_REPO"
```

起跑校验只证明可以开始，不证明 G2 通过。

## 3. 复现当前正式包红灯

先使用当前 API 依赖环境读取四个包，必须能复现 `0/4`；修复后同一入口必须得到 `4/4`。镜像只提供依赖，源码与内容包只读挂载当前工作树：

```bash
docker run --rm \
  -v "$MJ_V2_REPO:/repo:ro" \
  -e PYTHONPATH=/repo/apps/api \
  -w /repo \
  journey-next-api:latest \
  python -m pytest -q tests/test_construction_module_content_package.py
```

Mini 必须新增一项读取 `config/module-content-packages/*.module-content-package.v1.json` 的真实包测试，覆盖：

- 4/4 Runtime model validation；
- root 与每个 content/task/rubric hash；
- 任一嵌套字段漂移失败；
- Owner role、主备 Reviewer 重叠、不安全 data policy 失败；
- 业务字段变化触发 Owner 重新批准，而非静默重算。

修复原则：Runtime canonical hash 是唯一验收规则；生成器必须对**最终生成对象**计算 hash，并采用相同的时区规范化。不得继续对候选源片段计算 hash 后填入另一种对象。

## 4. 隔离运行 G2

先完成代码修复和定向测试，形成一个干净本地提交。然后记录完整 SHA：

```bash
MJ_V2_SHA="$(git rev-parse HEAD)"
test -z "$(git status --porcelain)"
```

API/数据库：

```bash
COMPOSE_PROJECT_NAME="$MJ_V2_PROJECT" \
MJ_DB_PORT="$MJ_V2_DB_PORT" \
MJ_API_PORT="$MJ_V2_API_PORT" \
MJ_WEB_PORT="$MJ_V2_WEB_PORT" \
make api-test migration-check openapi-check
```

Web：

```bash
make web-install web-check
```

合同、隔离与供应链：

```bash
make traceability-check legacy-reference-scan
make wp12-hardening-check wp12b-contract-check wp13-15-plan-check
make wp15-alpha-cutover-check wp15-wartime-cutover-check
make wp16-web-only-check wp17-prototype-check wp19-publication-web-only-check
make wp29-contract-check wp30-contract-check
make secret-scan dependency-audit
```

若 Makefile 内部调用 Compose，必须让 `COMPOSE_PROJECT_NAME` 和三项端口变量持续存在于该命令环境。不得因为旧容器或端口冲突去停止其他工作区。

## 5. 固定 SHA 后重跑，而不是给 dirty overlay 盖章

开发提交后，在独立 detached worktree 验证同一个 SHA：

```bash
MJ_V2_VERIFY_DIR="$(mktemp -d /tmp/mj-v2-verify.XXXXXX)"
git worktree add --detach "$MJ_V2_VERIFY_DIR" "$MJ_V2_SHA"
```

在 `$MJ_V2_VERIFY_DIR` 重跑 G2。所有证据写入：

```bash
mkdir -p "$MJ_V2_EVIDENCE_ROOT/$MJ_V2_SHA"
```

不得写回 detached worktree 或候选分支。候选 manifest 必须位于证据目录，以避免“写 manifest 改变 candidate SHA”的自引用。

## 6. 镜像、SBOM和漏洞扫描

三镜像标签必须包含完整候选 SHA，且构建上下文来自 detached worktree。记录 repo digest，而不是只记录 tag。

Trivy 镜像已存在，但本地漏洞库尚未验证。必须记录扫描器镜像 digest、数据库更新时间和命令退出码。数据库无法获取时保持：

`BLOCKED_EXTERNAL_SCANNER_DB`

不得复用旧镜像扫描结论。

## 7. 候选冻结

仅当 V2-02 至 V2-05 全部通过：

1. 在仓库外生成 candidate manifest；
2. 固定 full SHA、content index hash、migration head、配置 hash、三镜像 digest、SBOM hash 和测试证据；
3. 检查候选分支与 detached worktree仍指向同一 SHA；
4. 创建一次本地 annotated tag；
5. 不再修改候选提交，不 push、不部署。

若任一机器 Gate 未通过，只能输出 `BLOCKED` 或 `FAIL`，不能创建候选 tag。

## 8. 清理边界

V2 可以停止并移除自己创建的 `$MJ_V2_PROJECT` 容器，但不得触碰 `journey-next` 项目、生产容器或其他历史候选。临时 worktree 和证据保留到 Pro 复核完成；清理由 Pro 复核后另行决定。
