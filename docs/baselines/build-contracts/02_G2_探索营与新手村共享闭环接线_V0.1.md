## 1. 本阶段的人结果

探索营和新手村现有运行事实现在可以进入同一套共享语义：同一个 `User.id` 成为跨模块 Person；每个固定 SubmissionVersion 形成确定性的 Practice Evidence；最终 Review/Evaluation 形成 Human Evaluation Evidence 与 Human Gate；返工时旧版本和旧结论保留，重新提交形成新版本链。

这使后续共享 Evidence Ledger 不需要复制人员、提交、评价或 Outcome。但本阶段没有开放新的 Learner API 或页面，尚不能声称使用者已经看到跨模块证据账本。

## 2. 真实运行事实接线

| 既有权威事实 | 共享合同投影 | 关键不变量 |
| --- | --- | --- |
| `User.id + organization_id` | `PersonContract` | 不创建模块本地 Person |
| `TaskVersion + Assignment + SubmissionVersion` | `PRACTICE Evidence` | 固定版本、同组织、本人创建 |
| `Review(FINALIZED) + Evaluation` | `HUMAN_EVALUATION Evidence` | Reviewer 与固定提交版本一致 |
| `Evaluation.PASS / REVISION_REQUIRED` | `HumanGate.PASS / NEEDS_REVISION` | 由真人签署，不能自审 |
| `SubmissionVersion.version_no` | Evidence revision | 新版本引用立即前一版本，旧版本不覆盖 |
| 现有 `Outcome` | 运行结果事实 | 不因存在 Outcome 自动成为正式共享人才状态 |

投影 ID 使用固定 namespace 与不可变源 ID 生成 UUIDv5，因此重复读取同一事实得到同一 Evidence/Gate ID，不建立可任意写入的新账本。

## 3. 探索营接线

正式探索营测试路径继续执行 `Day 0 + 四宝藏 + 三项评测`。只有三项评测进入 Review/Evaluation；学习阶段的 Learner Evidence 完成不产生 Human Gate。

本阶段在真实测试库完成八阶段路径，并把最终 Assessment 的 Person、固定提交、FINALIZED Review 和 PASS Evaluation 投影到共享合同。由于 BC-001 的内容 Owner、最终 Rubric 和任务授权仍待签署，投影状态保持：

`TASK_AUTHORIZATION_PENDING`

现有 `JourneyAdmissionDecision.ADMIT/DEFER/NOT_ADMIT` 没有被映射为正式人才结论，也没有改写任何人事事实。

## 4. 新手村接线

本阶段只使用 `SYNTHETIC_TEST_ONLY` 任务，真实执行：

`领取 → 提交 V1 → 真人要求返工 → 提交 V2 → 真人通过 → Outcome`

共享投影证明：

- V1 Gate 为 `NEEDS_REVISION`，不能形成正式结果；
- V2 Practice Evidence 引用 V1 Evidence，旧提交和旧 Evaluation 保留；
- V2 Gate 为真人 `PASS`；
- 即使已有 PASS 和 Outcome，因为任务不是获批准的首批真实任务，正式共享状态仍为 `TASK_AUTHORIZATION_PENDING`；
- 全程不连接或写入任何生产系统。

冻结的 `newcomer-village-first-real-integration-action` 原型没有被修改或晋级，其自证草稿仍不能成为正式 Evidence。

## 5. 失败关闭规则

以下任一条件存在时，投影不得标为 `FORMAL_RESULT_ELIGIBLE`：

1. Human Gate 不是 `PASS`；
2. 首批任务授权不是 `APPROVED_CONTROLLED_TASK`；
3. Module 与 BC 绑定不一致；
4. Gate 类型与模块不一致；
5. TaskVersion、Assignment、Submission、Review、Evaluation 任一固定范围不一致；
6. Reviewer 等于 Person；
7. 修订缺少立即前一 SubmissionVersion；
8. AI 使用披露缺失或 AI 输出试图成为正式结论；
9. 任何调用声称 Journey 执行了生产动作。

标记为 `APPROVED_CONTROLLED_TASK` 的上下文不得使用含 `synthetic`、`test-only` 或 `pending` 的任务引用，避免测试数据被误提升。
