# BC-002｜新手村受控任务闭环 Build Contract V0.1

> 状态：`BUILD_STARTED_BY_DECIDER_OVERRIDE / TEAM_ACCEPTANCE_DATA_AND_SOD_PENDING / NO_REAL_TASK_OPEN / NO_RELEASE`  
> 开发授权：见 `../Muchen_Journey_全模块开发解锁决议_V0.1.md`；未签署项继续作为发布前Gate。
> MAP-ID：MAP-001、003—014、019—024  
> 权威方向：允许受控真实项目任务；Journey不直接执行生产作业；正式任务必须提交、审核、返工/通过。

## 1. 贡献契约

使用者是新手村学员、任务授权人、NPC/Reviewer和运营Owner。完成后，学员在清楚边界下完成一项对真实项目可使用的产出；Reviewer能从原任务版本、提交和Rubric完成审核返工；运营能看见队列、SLA、异常、积分来源和下一安排。

“与同事沟通了”“点击我已完成”“生成本地证据草稿”只能作为自查或草稿，不能构成正式任务完成。

## 2. 生产隔离边界

Journey可以：发布授权任务卡、展示脱敏输入、接收提交/证据、发起人工审核、记录结果、通知下一行动。

Journey不得：直接修改客户或生产系统、代表学员发送生产消息、持有超出任务所需的生产凭证、把未审核产物自动投递生产。

真实生产动作在受控业务系统中由获授权人员执行；Journey只接收该动作的最小证据或结果引用。

## 3. 每个真实任务的六项前置

任务发布前必须具备：授权人和用途；数据等级；脱敏方式；参与人与可见范围；指定Reviewer和替补；保留期限与删除/封存规则。缺一项即保持 `DRAFT`。

标准任务卡还必须显示：为什么做、输入、目标、非目标、交付物、截止时间、Rubric、求助/升级路径、积分规则（如有）。

## 4. 黄金路径

1. 项目Owner授权一项受控真实任务；Data/Security完成六项检查。
2. Content/运营Owner发布不可变TaskVersion并分配Reviewer。
3. 学员领取并开始任务；系统记录具体版本。
4. 学员在Journey外的受控环境完成必要业务动作，在Journey内提交产物或最小证据。
5. Reviewer按Rubric审核，必须选择返工或通过并写理由。
6. 返工保留旧版本；再次提交形成新SubmissionVersion。
7. 通过后产生Outcome/Handoff；积分账本可引用该贡献，但不能修改能力结论。
8. 学员看见完成事实、Reviewer、依据、积分和下一任务；运营看见SLA及异常。

## 5. 积分、AI和历史数据

积分只能在人工通过或明确的低风险行为事实后产生；积分记录必须引用来源事件。排行榜不得用于自动准入或人才结论。

AI可以检查缺项、敏感信息风险、Rubric初评和摘要；真人Reviewer对正式结论负责。

历史新手村数据先备份、盘点、字段映射、数量对账和抽样核验，再逐项标记 `MIGRATE / ARCHIVE_READ_ONLY / DO_NOT_IMPORT`；禁止在线直连旧库边跑边改。

## 6. 复用与重写

复用：TaskDefinition/Version、Assignment、Submission/Draft/Version、Attachment安全扫描、Review/Evaluation、Outcome/Handoff、Outbox/Notification、Audit、Offline Import、角色/权限和运营入口。

重写或补齐：主/支/隐藏任务业务类型、积分独立账本、申诉、Reviewer容量/SLA、真实任务授权字段和运营看板。

冻结候选：`newcomer-village-first-real-integration-action` 的隐私提示和行动卡交互可参考；其“自证真实行动→本地证据草稿”不得升级为正式黄金路径。
