## 1. 适用范围与使用者贡献

### 1.1 适用范围

本合同约束共享首页、成长地图、模块入口、任务卡与详情、行动工作区、AI 自查、正式提交、等待审核、返工、通过与结果、Reviewer 工作台、运营视图，以及锁定、空态、错误态、移动端和可访问性行为。

探索营、新手村、AI 学院和公会按当前已批准产品与内容合同接入。认证竞技场与 Career Map 只能在其业务合同、内容、角色、状态和发布 Gate 另行批准后复用本合同；本合同不提供隐含解锁。

### 1.2 使用者贡献

| 使用者 | 通过本体验层能够做成什么 |
| --- | --- |
| 学员/成员 | 看懂自己在哪里、为什么做、现在只做什么；完成实操、提交证据、接收返工或通过结论，并找到下一行动或申诉入口 |
| Reviewer/导师 | 在固定任务、提交版本和 Rubric 上完成可解释的返工或通过，保留理由、版本与责任人 |
| 运营人员 | 看见真实队列、SLA、锁定原因、异常、通知与升级路径，不用从技术字段猜测业务状态 |
| 授权 Owner | 从界面确认内容版本、状态来源、证据来源和人工责任边界，不把系统展示误作批准或发布事实 |

## 2. 权威层级

当来源冲突、缺失或不可验证时，界面按下列顺序取值，并失败关闭；低层不得覆盖高层。

1. 已批准的 Owner 决议、总产品合同、模块 Build Contract 与人工签署事实。
2. 已批准并绑定 hash 的四模块内容包、任务版本、Rubric、Reviewer、SLA 与数据边界。
3. 共享领域状态机、Evidence/Evaluation/Outcome/Handoff、人工 Gate、申诉、权限、隐私、安全和审计事实。
4. `PRODUCTION_CANARY_UAT`、候选冻结、恢复、独立复核与 Release 合同。
5. Mini/Journey 2.0 技术运行基线；只承接运行能力，不反向定义产品语义。
6. 本合同；只规定人本呈现、交互与失败关闭，不创设正式业务事实。
7. 外部产品启发；只可提炼低风险学习机制，不是 Muchen Journey 产品事实源。

任何机器结果、页面上线、点击、阅读记录、自证、AI 建议、积分、徽章、连续学习或排行榜均不得越级成为人工判断、正式能力结果、人才结论、Canary 授权或 Release 授权。

## 3. 共享体验原则

1. `HX-PRINCIPLE-001 单一下一动作`：每个可行动页面只突出一个真实、可执行、与当前权威状态一致的主动作；次要信息不得与主动作争抢决策。
2. `HX-PRINCIPLE-002 先意义后字段`：先用成人可理解的语言说明“为什么、做什么、做到什么程度、下一步是什么”，再按需展开版本、ID、hash 和审计元数据。
3. `HX-PRINCIPLE-003 五类事实分层`：完成事实、人工判断、AI 建议、积分激励、系统状态必须使用明确文字标签分别显示，不以颜色或图标单独区分。
4. `HX-PRINCIPLE-004 行动绑定证据`：正式进度只跟随权威状态和不可变证据；界面反馈不得领先于后端已确认事实。
5. `HX-PRINCIPLE-005 返工可继续`：返工不是惩罚；界面必须指出需要修改的项目、依据、保留的旧版本、求助方式和重新提交入口。
6. `HX-PRINCIPLE-006 低认知负担但不幼稚化`：语言简洁、有探索感、温度和及时反馈，面向成人职业成长；不使用儿童口吻替代清晰责任与标准。
7. `HX-PRINCIPLE-007 风险处失败关闭`：状态、证据、权限、版本或网络结果不确定时，不推断成功；保留用户输入，解释未完成事项，并给出安全恢复或升级动作。
8. `HX-PRINCIPLE-008 跨模块一致`：相同的任务、提交、审核、返工、通过、结果和申诉语义在所有模块保持一致；模块只提供经批准的内容差异。

### 3.1 五类事实显示词典

| 固定标签 | 用户可据此理解 | 不得混写为 |
| --- | --- | --- |
| `完成事实` | 已发生、可回链的行为或证据 | 能力结论或人才结论 |
| `人工判断` | 具名真人基于固定证据和 Rubric 签署的判断 | AI 评分或系统推断 |
| `AI 建议` | 可采纳、可拒绝、带来源和不确定性的辅助信息 | 正式通过、返工或下一阶段决定 |
| `积分激励` | 对已发生低风险贡献事实的独立激励记录 | 正式进度、能力或准入依据 |
| `系统状态` | 服务端已确认的流程位置、权限或运行事实 | 对人的评价 |

## 6. 可学习机制合同

### `HX-LEARN-001` 今日主任务

- 人的使用目的与真实问题：让用户在进入 Journey 后立即知道“今天只做什么”，减少多模块、多任务并列造成的选择负担。
- 允许输入及来源：仅使用有效 Enrollment、正式 Assignment、截止时间、Reviewer SLA、已批准推荐规则和当前权威状态；不得以积分高低或 AI 人才推断选主任务。
- 页面行为和反馈：共享首页只突出一项今日主任务，说明为什么现在做、预计用时、完成标准和下一步；完成低风险学习输入后可即时确认行为事实，正式任务则只显示权威流程状态。
- 状态/证据/人工 Gate 绑定：进入正式任务只能触发既有 `AVAILABLE → IN_PROGRESS`；提交、返工和通过仍分别依赖 SubmissionVersion、Evaluation 和真人 Gate。
- 适用模块：共享、探索、新手、学院、公会。
- 风险边界与不可产生结论：主任务排序不构成能力、录用、淘汰、项目准入、晋升或绩效结论；来源不唯一时不自动选择，转为空态或运营确认。

### `HX-LEARN-002` 支线任务

- 页面行为和反馈：支线与今日主任务分区，明确标记“可选、不影响正式结果”，显示预计时间、收益和退出后回到主线的路径。
- 状态/证据/人工 Gate 绑定：支线阅读或点击只产生低风险行为事实；若支线被另行批准为正式任务，必须回到统一 Assignment、提交、审核、返工/通过闭环。

## 8. 禁止机制合同

阶段状态：`CHECKPOINT_3_PROHIBITIONS_WRITTEN / OWNER_REVIEW_REQUIRED / NO_RELEASE_AUTHORITY`。

本节定义可由静态检查、自动化负向测试、审计查询和真人 UAT 共同验证的停止线。命中任一条款时，页面不得用提示文案掩盖错误业务行为；必须执行该条款的失败关闭动作，并保留原始证据、事件编号和处理责任链。

### `HX-BAN-001` AI 代替真人作出正式结论
