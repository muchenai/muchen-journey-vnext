## 1. 人结果与非目标

目标是在 2026-09-01 前交付供魔鬼训练营 2.0 实际使用的四模块受控首发，不是完整 Journey2.0 正式版。参与者必须能在同一身份和同一任务引擎中完成：模块进入、任务领取/选择、实操、证据提交、真人审核、返工或通过、结果包查看。

本合同不建设完整认证竞技场、完整认证体系、Career Map 复杂计算、积分兑换、跨模块自动准入或 Legacy 数据迁移。Journey 不执行客户生产动作；AI、积分和自证不能产生正式能力或人才结论。

## 2. 唯一共享纵切

`MODULE_ENTRY → TASK_ASSIGNMENT_OR_SELECTION → PRACTICE → EVIDENCE_SUBMISSION → HUMAN_REVIEW → REWORK_OR_PASS → RESULT_PACKAGE`

四模块必须复用 `User/Organization → Enrollment → Assignment → Submission/SubmissionVersion → Review/Evaluation → Outcome/Handoff`。不得建立第二套 Person、Task、Submission、Review、Evidence 或 Result 事实源。

## 4. 候选冻结与工作树

- 当前继承的未提交工作必须先备份，再逐文件归属为 `RELEASE_REQUIRED / POST_RELEASE_DEFERRED / RELATED_EVIDENCE / UNKNOWN`；
- 候选 manifest 只允许收录明确的 `RELEASE_REQUIRED` 文件及必要配置/内容包；
- 候选必须绑定完整 commit SHA、配置 SHA、Alembic revision、Web/API 构建产物和内容包版本；
- 工作树不干净时可以生成“候选输入快照”，但不能称为最终 Release Candidate；最终 RC 必须由明确 commit SHA 唯一复现；
- 任一候选字节变化使候选级 UAT、独立 QA 和 Release Review 签署失效。

## 5. 真人和独立复核

冯宇汀的独立 QA 与独立 Release Reviewer 任命和接受已经 Owner 确认。因此：

- `INDEPENDENT_QA_UAT_NOT_APPOINTED=RESOLVED`；
- `INDEPENDENT_RELEASE_REVIEWER_NOT_APPOINTED=RESOLVED`。

但角色接受不等于候选级签署。当前固定为：`HUMAN_UAT=NOT_RUN`、`INDEPENDENT_QA_SIGNOFF=NOT_RUN`、`RELEASE_REVIEW=NOT_RUN`、`RELEASE_AUTHORIZED=false`。

四模块每个至少 2 名真实目标用户，均须对同一候选 SHA 完整执行登录到结果包的端到端场景。UAT 证据必须绑定场景版本、人数、步骤结果、P0/P1/P2、QA/UAT 运营确认、模块 Owner 确认和独立 QA 复核。
