## 4. 签署会议必须逐项回答

### 共通问题

1. 模块服务谁，用户在什么时点用它完成什么任务？
2. 哪些是学习/点击/AI建议，哪些才是正式证据和真人结论？
3. 谁能创建、审核、返工、通过、撤销、申诉和查看？
4. 哪个系统是权威载体，保留多久，错误如何更正？
5. 首次上线用什么真人任务验证；失败时谁在多久内处理？
6. 哪三种负向情况必须被系统拒绝？

## 7. 签署会议建议产出

一次90分钟会议不应试图签完所有细节。建议只产出四个确定结果：

1. 确认13类责任中的姓名和接受日期；
2. 先签 BC-001、BC-002 的首批对象与Owner，恢复 W1/W2；
3. 给 BC-003—BC-006 各指定一个内容/治理补齐截止日；
4. 对历史数据、真实任务和发布 Gate 明确 `NO_GO` 解除证据。

会议结束后若没有姓名、日期和首批对象，则不应把“原则同意”记录为批准开发。
