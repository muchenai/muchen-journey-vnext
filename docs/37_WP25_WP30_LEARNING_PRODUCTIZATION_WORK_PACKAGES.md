## 1. 本次重排的结论

V0.1 虽然补上了视觉、内容、学习进度和发布，但仍按“视觉组件 → 数据模型 → 内容后台 → Learner 页面 → 服务端门禁 → 最后真人 UAT”的技术层顺序推进。它把真人理解和参与感继续推迟到 WP-30，仍可能出现代码和文档全部通过、目标用户第一次使用才发现产品不成立的问题。

本版改为结果优先：

```text
真实内容与完整体验先冻结
  → 先让目标用户操作完整高保真旅程
  → 只实现一个真实宝藏纵向切片
  → 真人证明有效后扩展四宝藏
  → 接入三评测、修订与人工准入
  → 最后形成固定候选并受控上线
```

每个工作包都必须交付一个真人可感知的结果，并在进入下一包前完成小样本人测。自动化只能证明系统按合同运行，不能证明页面看得懂、内容值得学或用户愿意继续。

## 2. P0 到底交付什么

### 2.1 唯一产品承诺

一名从未接触公司、项目或模型评测岗位的 Learner，通过私密邀请进入后，能在没有运营口头指导的情况下：

1. 看懂这是一段 Day 0＋四个宝藏＋三个能力评测的一天旅程；
2. 知道自己在哪里、为什么做这一站、下一步是什么；
3. 先获得真实学习材料，再完成与本主题直接相关的小任务；
4. 随时退出并安全恢复，不丢材料进度、草稿、提交或反馈；
5. 感知到真实 Reviewer 的存在、反馈状态和处理预期；
6. 经历提交、要求修订、重新进入、再次提交和通过；
7. 在结果页看见自己的证据、结论和下一步，而不是只看到系统状态。

“有参与感”不等于加积分、徽章或游戏皮肤。P0 的参与感来自清晰位置、连续进展、真实选择、即时状态反馈、真人回应和可感知完成。

### 2.2 P0 体验硬指标

| 指标 | P0 门槛 | 证据 |
| --- | ---: | --- |
| 首次定向 | ≥90% Learner 在 10 秒内说出当前位置和下一步 | 真人观察 |
| 首个有效动作 | ≥90% Learner 在 60 秒内自主进入第一份材料 | 浏览器事实＋真人观察 |
| 输入先于输出 | 100% 宝藏先有材料，未完成材料不能开始小任务 | API/浏览器＋真人 |
| 会话连续性 | 刷新、退出、重新登录和换设备不丢权威进度/草稿/反馈 | 自动化＋真人 |
| 路线可信度 | 390/768/1280 下节点中心落在线上，状态和标签不冲突 | 视觉回归＋人工 |
| 无死路 | 目标路径中意外 401/403、空白页、无下一步和丢事实均为 0 | 浏览器＋审计 |
| 支持介入 | 完成旅程时需运营解释或代操作的 Learner ≤20% | QA Recorder |
| 完整闭环 | 至少 1 条真实 `提交→修订→重进→再提交→通过→结果` | 私密 UAT 证据 |
| 体验评价 | “进度清楚”“愿意继续下一站”两项中位数均 ≥4/5 | 简短退出问卷 |

小样本指标用于发现阻断和判断是否扩大名单，不用于统计显著性或宣传。

### 2.3 “上线”与“验证完成”分开

- `P0_LIVE_CONTROLLED`：固定 Journey V3 已通过 P0 候选 UAT，并在 `journey.muchenai.com` 向私密小名单开放；staging、维护页和上一稳定版本继续保留。
- `P0_VALIDATED`：首批真实 cohort 完成后，体验、完成、支持介入和事实完整性达到上述门槛。
- 完整 production release gate 在外部观测、通知、独立恢复、批准和观察窗关闭前仍为 `NO_GO`；P0 受控上线不得被写成企业级 GA。

## 3. 固定产品和安全边界

### 3.1 内容必须先于代码

- 指定 Content Editor 在 WP-25 开工前提供 Day 0、四宝藏、三评测、Rubric 和结果说明的最终脱敏材料包；
- 每个宝藏必须同时有学习目标、材料、材料来源、本主题小任务、交付边界和自检；
- 缺真实材料的页面不得用工程师编写的解释性占位文案进入开发；
- 真实姓名和飞书身份只进入私密名册，Public Git 仅记录职责和 PII-free 证据引用。

### 3.2 版本不可变

- Journey V1/V2、既有邀请、Enrollment、Assignment、Submission、Evaluation、Outcome 和 AdmissionDecision 保持不可变；
- 本列车只创建新的 TaskVersion/JourneyVersion，暂称 Journey V3；
- 在途 Learner 不自动迁移，旧邀请不自动改绑，V3 只由 Operator 在 WP-30 明确发布。

### 3.3 材料与权限边界

- Alpha 仅支持清洗后的结构化文本和带来源说明的 HTTPS 外部链接；
- 不支持文件上传、PDF/视频对象存储、任意 HTML、后端抓取、网页嵌入、通讯录、AI 生成或推荐；
- WP-10 保持 `SECURELY_DISABLED_FOR_ALPHA`；真实使用证明附件不可缺时再单独重开五项物理门禁；
- Content Editor 只能管理本组织未发布草稿和预览；Operator 保留最终发布；Content Editor 不获得邀请、身份、Reviewer、准入、他组织或运行环境权限。

### 3.4 视觉与语言边界

- 路径与节点使用同一 SVG `viewBox` 和坐标源；只允许标签偏移，节点不得脱离路线；
- 首屏只有一个命题、一个状态、一个主操作；同一动作不在标题、说明、按钮和页脚重复；
- hover、focus 和 touch 只补充一句短说明，不能把说明书常驻在主画面；
- 每屏先表达“位置/状态/动作”，必要文字再表达约束；
- 不新增积分、徽章、排行榜、角色皮肤、抽奖或无产品含义的动效。

## 5. WP-25｜P0 Experience & Content Freeze

### 5.1 目标

在编码前锁定“学什么、为什么做、页面如何引导、每一步看见什么”，把设计从方向文档升级为可直接验收的完整产品合同。

### 5.2 交付物

- 由 Content Editor 确认的 Day 0、四宝藏、三评测、Rubric 和结果说明材料包；
- 从邀请、首页、地图、材料、小任务、等待反馈、修订、通过到结果的完整高保真可点击原型；
- 390/768/1280 三视口关键页面和 hover/focus/touch/reduced-motion 状态；
- 页面状态矩阵、唯一主操作、文案预算、错误/空态/恢复态和内容来源清单；
- “设计事实 → route/state/content/API”的实现追踪表。

### 5.3 真人门禁

- 至少 3 名符合目标画像、未参与设计的真实体验者独立操作原型；
- 10 秒定向、60 秒首个有效动作和“先材料后任务”全部达到 P0 门槛；
- 任何需要讲解入口、解释重复文案、猜测节点含义或面对无输入作答的情况均为 FAIL；
- Content Editor、Reviewer、Operator 分别确认材料、Rubric 和责任边界。

### 5.4 验收

- `AT-WP25-001`：完整材料包无占位、无未授权正文、无 PII，四宝藏各有真实输入和小任务；
- `AT-WP25-002`：完整原型覆盖正常、等待、修订、恢复、通过和错误状态，不只覆盖三张理想页面；
- `AT-WP25-003`：三名目标用户达到首次定向和首个有效动作门槛，原始失败不被口头指导覆盖；
- `AT-WP25-004`：三视口路线节点、标签、主操作和文字预算经 Design/Content/QA 联合签署；
- `AT-WP25-005`：实现追踪表没有“待开发时再决定”的 P0 页面、文案、内容或状态。

### 5.5 非范围

代码、migration、API、权限、部署、发布、邀请和运行资源。WP-25 是产品开工门禁，不是开发包。

## 6. WP-26｜One Treasure Real Slice

### 6.1 目标

只选择一个真实宝藏，把“内容负责人准备材料 → Operator 固定版本 → Learner 学习 → 小任务 → Reviewer 修订/通过 → Learner 恢复”一次做通；用它验证产品合同和最小数据模型，而不是先建通用平台。

### 6.2 范围

- 最小 `materials[]` 版本 schema、Content Editor scope、草稿/预览和 Operator 发布保护；
- 不可变 `LearningMaterialCompletion`，只证明 Learner 显式确认固定材料，不证明掌握；
- 一个宝藏的材料页、进度、任务解锁、草稿、提交、等待、反馈和安全重新进入；
- 路线/节点共享坐标、唯一主操作和适用的 accessibility 合同；
- 服务端拒绝未完成 required materials 的 start/submit、跨组织、跨版本和伪造 material key。

### 6.3 真人门禁

- Content Editor 无工程师代操作完成该宝藏材料草稿、预览和提交复核；
- 至少 2 名目标 Learner 无口头指导完成材料和小任务；
- 1 名独立 Reviewer 对其中一条提交要求修订，Learner 重新进入后修改并通过；
- 页面不得出现未学习就要求写作、意外 401/403、事实丢失或无下一步。

### 6.4 验收

- `AT-WP26-001`：最小内容权限、组织/对象隔离、发布不可变和 V1/V2 指纹回归通过；
- `AT-WP26-002`：required materials 是服务端不变量，点击、停留时间和滚动不自动表示完成；
- `AT-WP26-003`：刷新、会话轮换、重新登录和换设备恢复固定版本、进度、草稿与反馈；
- `AT-WP26-004`：两名 Learner 与独立 Reviewer 完成真实单宝藏修订闭环并达到体验门槛；
- `AT-WP26-005`：只实现一个宝藏所需字段和 UI，没有通用 CMS、第二套答案系统或推测性抽象。

### 6.5 非范围

其他宝藏、三评测、批量内容、多人协同、附件、通知、AI、排行榜和正式域名开放。

## 7. WP-27｜Four Treasures Learning Journey

### 7.1 目标

复用已经由真人验证的单宝藏模式，完成 Day 0＋四宝藏的真实学习旅程；不引入第二套交互模型。

### 7.2 范围

- Content Editor 导入四宝藏最终材料、排序、预览和复核准备；
- Learner 路线、当前位置、锁定/可继续/完成状态、材料目录、主题小任务和跨站恢复；
- 站点推进只由服务端固定版本和事实投影决定；
- 当前卡只显示阶段、标题、必要提示和一个主操作；删除同义说明和页脚；
- 外部 HTTPS 链接显示真实目标域名，服务端不抓取，Learner 返回后仍须显式确认。

### 7.3 真人门禁

- Content Editor 独立完成全部四宝藏草稿，不通过工程师改 seed 或直写数据库；
- 至少 1 名 Learner 完成 Day 0＋四宝藏，另 2 名 Learner 完成前两个宝藏；
- 三名 Learner 均能说出当前位置、已完成、下一站和为什么尚未解锁；
- 不允许运营替用户寻找入口或解释重复文案。

### 7.4 验收

- `AT-WP27-001`：四宝藏全部使用批准材料、真实小任务和稳定 material key，没有占位内容；
- `AT-WP27-002`：390/768/1280 的所有节点落在线上，键盘/触摸提示等价且标签不遮挡；
- `AT-WP27-003`：退出、恢复、错误重试和跨站推进不丢事实、不重复完成、不跳站；
- `AT-WP27-004`：真人学习路径达到定向、首动作、支持介入和主观体验门槛；
- `AT-WP27-005`：WP-26 交互和数据模型被复用，没有为四站复制四套状态或组件。

### 7.5 非范围

三项能力评测、人工准入、真实通知、自动学习判断、内容推荐和正式发布。

## 8. WP-28｜Assessments, Feedback & Admission

### 8.1 目标

把三项真实评测、真人 Reviewer 陪伴、修订闭环、完整结果和 Operator 人工准入接到四宝藏之后。

### 8.2 范围

- 复用 WP-24 已批准的规则拆解、模型判断、通用数据构建题面和固定 Rubric；
- Learner 清楚看到 Reviewer 身份代号、当前反馈状态、处理预期和唯一下一步；
- Reviewer 继续使用专业工作台，不添加游戏皮肤；
- 至少一项评测支持 `SUBMITTED → IN_REVIEW → NEEDS_REVISION → SUBMITTED → COMPLETED`；
- 结果页区分学习完成、能力证据、Reviewer 结论、系统建议和 Operator 人工准入。

### 8.3 真人门禁

- 2 名独立 Reviewer 完成题面/Rubric 校准；
- 至少 1 名 Learner 完成三评测和一次修订后通过；
- Operator 只能在完整证据后 preview 并作出不可变 `ADMIT/DEFER/NOT_ADMIT`，系统不得自动录用或淘汰；
- Learner 能理解“谁在看、现在等什么、什么时候回来、通过后去哪”。

### 8.4 验收

- `AT-WP28-001`：三评测身份、版本、Rubric、分值和 Reviewer scope 固定且组织隔离；
- `AT-WP28-002`：真实修订、重新进入、历史保留和最终通过全链路无意外授权错误；
- `AT-WP28-003`：等待和反馈页面体现真人责任与处理预期，但不伪造在线、已读或送达；
- `AT-WP28-004`：完整性服务端强制，缺任一宝藏/评测时拒绝 Outcome 和准入；
- `AT-WP28-005`：真人 Reviewer/Learner/Operator 能区分学习事实、能力评价、系统建议和人工决定。

### 8.5 非范围

自动招聘决定、真实消息推送、全量通讯录、AI 批改、排行榜和 HR 系统集成。

## 9. WP-29｜P0 Release Candidate UAT

### 9.1 目标

冻结唯一 Journey V3 候选并完成最后一轮上线前整日真人验证。WP-29 是最后的 P0 发布前 UAT，不允许借机加入“顺便优化”的新功能。

### 9.2 最小名册

- 1 Content Editor、1 Operator、至少 3 名真实 Learner、2 名独立 Reviewer、1 QA Recorder；
- 5 名 Learner 是推荐样本，3 名是受控 P0 最低门槛；同一人不得模拟全部角色；
- 名册、身份、链接、作答和截图只进入私密证据。

### 9.3 执行规则

- 使用固定候选、固定 V3 内容、固定浏览器清单和完整 10:00–19:00 路线；
- QA Recorder 只记录时间、结果、问题编号和 PII-free 引用，不在现场教用户操作；
- 问题只分为 `P0_BLOCKER` 与 `POST_LAUNCH_BACKLOG`；外观偏好和增强项不得阻止上线；
- P0 blocker 修复后只重验受影响路径；除非候选、数据合同或 JourneyVersion 改变，不重跑全部历史门禁；
- 一旦机器或真人证据失败，原始失败保留，不用口头确认覆盖。

### 9.4 验收

- `AT-WP29-001`：至少 1 名 Learner 完成整日四宝藏＋三评测＋修订＋结果闭环；
- `AT-WP29-002`：全部参与 Learner 达到适用的定向、首动作、无死路、连续性和支持介入门槛；
- `AT-WP29-003`：内容准确、题面可做、Reviewer 可评分、Operator 可准入，四类角色无越权；
- `AT-WP29-004`：390/768/1280、键盘、触摸、文本放大、reduced-motion、console 和 overflow 通过；
- `AT-WP29-005`：所有 P0 blocker 为 0；未关闭项均明确进入上线后 backlog，不伪装成 PASS。

### 9.5 退出

全部通过后只形成 `P0_RC_SIGNED`。这不自动部署、不自动发布 V3、不创建邀请，也不改变完整 production `NO_GO`。
