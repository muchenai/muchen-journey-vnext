# 41｜P0 产品闭环修复与真实反馈计划

文档状态：`IMPLEMENTED_LOCALLY / MACHINE_VERIFIED / NOT_DEPLOYED / HUMAN_UAT_PENDING`  
日期：2026-08-11  
Owner：Product + Tech + QA/UAT

## 1. 结论先行

Muchen Journey 的核心业务并不复杂；持续出现小问题的主要原因也不是状态机本身，而是此前用“模块、接口、门禁分别完成”代替了“新人从邀请走到结果”的整条产品完成定义。

基础设施、身份、权限、不可变事实和发布恢复解决了系统能否安全运行，但没有自动解决以下用户问题：

- 第一次接受邀请是否只需一个明确动作；
- 中断一天后能否继续，而不是重新找运营；
- 学习材料是否真的可以打开；
- 页面是否只呈现当前目标与下一步，而不是把内部合同写给新人看；
- Reviewer 要求修订后，Learner 是否能看懂、修改、再提交并最终看到结果；
- 运营是否能从状态名称判断下一步，而不是靠猜测邀请是否已兑换。

因此，本轮不增加新模块，不扩展基础设施，只关闭真实旅程上的断点，并建立一条不可由接口测试替代的完整浏览器合同。

## 2. 根因复盘

### 2.1 完成单位选错

过去的完成单位偏向 API、页面、迁移、部署 phase 和单项门禁。它们分别正确，仍可能在组合处失败。本轮实际发现的断点均位于组合边界：邀请兑换与身份确认之间、匿名页面与受保护页面之间、文本材料与外链之间、Reviewer 定稿与 Learner 当前行动之间。

### 2.2 浏览器验证覆盖了“页面可达”，没有覆盖“产品可完成”

既有 browser smoke 能证明路由、401、视口和 console 基本健康，但没有让一个 Learner 真实走完八站，也没有让 Reviewer 在中途要求修订。因此文案、导航等待、会话连续性和最终结果只有人工偶发触发，问题发现时间被推迟到上线前后。

### 2.3 把内部合同暴露成用户交互

为了确保状态、证据和权限明确，页面逐渐把大量工程解释直接呈现给 Learner。结果是系统安全边界更清楚，但交互更像读文档。正确做法是：合同留在服务端和按需展开区域；首层界面只保留当前位置、当前目标、唯一主动作和动作结果。

### 2.4 环境与身份路径过多，人工验证不可重复

local fixture、staging 飞书身份、production 飞书身份、Learner 邀请会话和 Reviewer/Operator 会话各自合理，但此前缺少统一的角色浏览器夹具。测试容易误把匿名拒绝、旧会话、浏览器不匹配或环境提示错误当成业务失败，修复也容易只覆盖当前浏览器现场。

## 3. 本轮 P0 修复范围

已在独立分支实现并通过本地机器验证：

1. 新邀请在同一页面完成兑换和身份确认，用户只点击一次“开启旅程”；原两步路径保留为失败后的安全恢复，而非主交互。
2. Learner 会话默认 24 小时，配置上限固定为 24 小时；Reviewer、Operator、Content Editor 的员工会话仍保持原 8 小时边界。
3. 重新进入链接明确进入既有 Enrollment，不创建新的业务事实。
4. `/ops` 将邀请区分为“待使用 / 已兑换，待确认身份 / 已使用 / 已撤销 / 已过期”，已兑换但未确认的邀请可由 Operator 撤销。
5. 固定 TEXT 学习材料中的绝对 HTTPS URL 被安全渲染为可点击链接；不使用任意 HTML 注入。
6. production 页面显示明确的 production 环境提示，不再落入 local/test 文案。
7. 修正移动端路线提示导致的横向溢出，并阻止首页 Reviewer OAuth 链接被浏览器预取。
8. 新增一次性 Journey V3 浏览器黄金路径：接受邀请、八站学习与提交、Reviewer 要求修订、Learner 再提交、Reviewer 通过、剩余评测和最终结果页。

## 4. 机器证据与边界

本地隔离证据：

- Web contract：31/31 通过；
- API：326 通过、5 跳过；
- TypeScript、ESLint、OpenAPI、迁移静态检查、隔离检查、追溯检查通过；
- 桌面/平板/手机 browser smoke 通过；
- Journey V3 浏览器黄金路径通过：`invite=one_step / stages=8 / revision=resubmitted / reviewer=complete`；
- 浏览器测试使用一次性数据库、PII-free 合成任务和临时 Learner/Reviewer 会话；结束后删除容器与卷，不保留令牌。

该证据只证明产品链路在隔离浏览器中可完成，不证明真实新人理解内容，也不构成 production 部署、真人 UAT 或 cohort 成功。

## 5. 接下来的唯一产品节奏

### Batch A｜48 小时闭环修复

退出条件：上述代码通过 PR、候选和 staging 受影响路径复验。不得并行增加通知、附件、分析、AI 或基础设施能力。

### Batch B｜一周 Learner Experience 收敛

每页只保留一个目标和一个主动作；解释内容默认折叠；完成材料、提交、等待、修订、通过均提供即时状态变化和唯一下一步。该批次不改变业务状态机，只重构信息层级、反馈和导航。

### Batch C｜小规模真实使用

先由 1 名未接触项目的真实新人独立完成，再扩大到 3–5 人。只处理入口、理解、学习、提交和评审阻断；偏好型视觉建议进入 backlog，不阻止真实使用。

最小验收：

- 新人 3 分钟内进入第一站；
- 正式学习链接 100% 可打开；
- 邀请、会话和状态无需 Operator 口头解释；
- 每页能指出当前位置和唯一下一步；
- 要求修订、重新进入、再次提交、通过和结果页闭环成功；
- 5 名真实 Learner 中没有 P0 阻断缺陷。

## 6. 停止规则

- 不再用新增文档、更多模拟角色或更多基础设施代替真实新人反馈。
- 不因非阻断的视觉偏好延后小范围真实使用。
- 任一身份越权、业务事实重复/丢失、正式链接不可达、无法提交/修订/评审/恢复，立即停止扩大 cohort。
- 自动化通过不得写成真人 UAT 通过；真人反馈不得反向要求绕过身份、审计或不可变事实底线。

## 7. Batch B｜Learner Experience 本地实现证据

2026-08-11 已完成第一轮信息层级收敛，未改变 API、迁移、权限或业务状态：

1. 任务页一次只展开当前学习材料；完成后解锁下一项，后续材料不再同时展示正文和动作。
2. 必读材料完成前不渲染作答区，避免新人刚进入任务就面对空白文本框；首层只保留当前材料与“完成并继续”。
3. 操作步骤、完成标准、交付内容、提交历史、评审边界改为按需展开，仍保留完整合同和不可变证据。
4. 重新进入页移除 Enrollment、Assignment 等内部术语，只说明“从上次离开的地方继续”。
5. 结果页首层从五个信息区收敛为结论、能力反馈、唯一下一步；通知状态与过程记录合并到按需展开区。
6. TEXT 材料中的 HTTPS 链接显示为可识别域名并保留“打开学习材料”的无障碍名称，避免“请打开 打开学习材料”式重复文案。

本地机器验证：

- `make ci-fast` 通过：API `326 passed / 5 skipped`，Web contract `31/31`，OpenAPI、隔离、追溯、secret scan、npm/pip 依赖审计通过；
- Journey V3 浏览器黄金路径再次通过：一次加入、八站、要求修订、重新提交、Reviewer 完成、结果页；
- 第一站任务页在 `1280×900 / 768×1024 / 390×844` 三种视口均满足：仅一项材料展开、仅一个主动作、作答区未提前出现、无横向溢出；
- 公开入口三视口 smoke 通过，匿名受保护路由和 Content Editor 安全重新进入合同保持不变；
- 截图与浏览器日志保存在本地 `output/playwright/`，不纳入产品源码，也不构成真人 UAT。

该批次当前仍为 `IMPLEMENTED_LOCALLY / MACHINE_VERIFIED / NOT_DEPLOYED / HUMAN_UAT_PENDING`。下一门禁仍是先由 1 名未接触项目的真实新人独立完成，再扩大至 3–5 人；机器浏览器不能代替理解度、参与感和一天完成体验的真人结论。
