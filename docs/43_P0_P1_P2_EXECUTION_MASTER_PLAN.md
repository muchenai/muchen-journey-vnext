# 43｜P0、P1、P2 总施工计划

状态：`APPROVED_FOR_BUILD / P0-1_CLOSED / P0-2_IN_BUILD`
版本：V1.0
日期：2026-08-13
上位合同：[42｜第一性原理产品与工程总基线](42_FIRST_PRINCIPLES_PRODUCT_AND_ENGINEERING_BASELINE.md)
Owner：Product Owner + Tech Lead + Design Owner + QA/UAT Owner + Release/Ops Owner

## 1. 总目标与顺序

未来施工只按用户风险和信息价值排序：

- **P0：让探索营可被真实新人和主管稳定使用。** 解决“进不去、看不懂、做不完、评不了、恢复不了”。
- **P1：让小范围运营可持续。** 解决“内容难维护、运营靠人工、问题看不见、反馈无法收敛”。
- **P2：在真实使用证明价值后扩展。** 解决多组织、规模、通知、附件、灾备故障域和更丰富体验。

P0 未达到 `P0_LIVE_CONTROLLED` 且连续真实使用稳定前，不启动 P2。P1 可做 discovery，但不能与 P0 共享合同并行施工。

## 2. 当前真实起点（2026-08-13）

已具备：

- vNext 独立仓库、数据库、staging/production 逻辑环境与冻结基础设施；
- 邀请、Enrollment、任务版本、提交版本、人工评审、修订、结果和审计基础；
- Journey V3、Day 0、四宝藏、三评测的内容/编排基础；
- staging 可用，正式域名有受控 Alpha 运行与回退能力；
- 私密名册中的当前内容主管，其 Content Editor 与 Reviewer 角色授权事实已存在且有审计；同一飞书身份已真人复验 `/content` 与 `/review` 均正常。

仍未关闭：

- Learner 材料、任务要求、链接与页面信息层级仍有真实可用性缺陷；
- Journey V3 尚未由独立真人完成全路径；
- 当前 release gate 的完整 UAT、外部通知、异机恢复、审批和观察窗口仍为 `NO_GO/NOT_RUN`；
- 运营反馈、支持指标和 P0 缺陷收敛机制未形成稳定节奏。

## 3. P0｜可真实运营的探索营

### P0-0｜冻结与清场（0.5 天）

用户结果：团队只处理影响真实探索营使用的一个缺陷队列。

施工：

- 冻结新功能、基础设施增强和非 blocker 视觉优化；
- 把所有已知问题按主路径阶段归类，不按技术模块归类；
- 标记当前唯一 staging 候选、Journey V3、内容版本和测试名册；
- 建立 P0 blocker 看板：进入、学习、提交、评审、修订、结果、运营、恢复。

退出 `AT-P0-000`：只有一个候选、一个 Journey V3、一个 blocker 清单、一个 Owner；没有并行产品 WIP。

### P0-1｜身份中心化与多角色访问（2–3 天）

用户结果：私密名册中的当前内容主管以本人同一飞书身份登录一次，可进入 Content Editor 和 Reviewer；Operator 授权后无需重新绑定身份。

施工：

- 把 session principal 从单一 role 改为 `user + organization + identity_version`；
- 增加服务端 active capabilities 解析和 `/me`/页面导航能力返回；
- `/content`、`/review`、`/ops` 基于 active RoleAssignment + scope 授权；
- 角色授予/撤销使旧 capability cache 立即或有界失效；
- 统一无会话、身份撤销、无角色和 scope 不匹配的错误/重新进入路径；
- 保留历史撤销与审计，不直接改库修复。

验收：

- `AT-P0-101` Content Editor 增加 Reviewer 后刷新即可进入 `/review`；
- `AT-P0-102` `/content` 继续可用；
- `AT-P0-103` 无 Reviewer 的身份访问 `/review` 返回友好拒绝且不泄露队列；
- `AT-P0-104` 撤销 Reviewer 后现有会话失去 Reviewer 能力但其他角色不受影响；
- `AT-P0-105` 撤销 ExternalIdentity 后全部相关会话失效；
- `AT-P0-106` 真实 Chromium 完成飞书 OAuth → `/review`，无 `AUTH_REQUIRED/FORBIDDEN` 循环。

停止条件：若实现需要为每个角色复制 ExternalIdentity 或登录回调，停止并回到模型评审。

### P0-2｜Learner 一站式任务页收敛（2–3 天）

用户结果：新人进入任一站后 5 秒内知道目标、输入和唯一下一步，不会在没有学习输入时先遇到空白写作框。

施工：

- 学习材料渲染为明确可点击链接，启动前执行 URL 可达性/格式只读校验；
- 任务要求首次进入默认展开；完成后可折叠但保留入口；
- 页面按“当前站 → 学习输入 → 要求 → 输出 → 提交”排序；
- 删除标题、按钮、脚注和卡片间的重复文案；
- 路线点和路线使用同一坐标数据，桌面/平板/手机不漂移；
- 错误页提供恢复按钮和事实是否保存说明，不裸露 JSON。

验收：

- `AT-P0-201` 三名未看说明的新用户 5 秒测试全部说出当前目标和下一步；
- `AT-P0-202` 八站的所有必读材料均能从 UI 打开；
- `AT-P0-203` 首次进入八站，任务要求均默认可见；
- `AT-P0-204` 页面默认解释文字满足预算且无重复动作；
- `AT-P0-205` 390/768/1280 的路线点在线、无横向溢出；
- `AT-P0-206` 会话过期、链接无效和服务失败均提供安全重新进入路径。

### P0-3｜完整 Journey V3 真人闭环（1–2 天执行）

用户结果：真实 Learner 一天内完成四宝藏和三评测；真实 Reviewer 完成评审，至少一次修订；Operator 能处理异常并看到最终结果。

受控 P0 最小名册：3 名 Learner、1 名私密名册 Reviewer、1 名 Operator、1 名 QA Recorder。先单组织，不以规模代替可用性。该最小样本用于判断“能否受控运营”，不关闭 DEC-007 规定的 5 名 Learner + 2 名独立 Reviewer 完整发布 UAT；后者继续作为 `RELEASE_GO` 门禁。

必走路径：

1. 新邀请进入；
2. Day 0 与四宝藏材料/小任务；
3. 三项能力评测提交；
4. Reviewer 对至少一项要求修订；
5. Learner 安全重新进入并再次提交；
6. Reviewer 通过；
7. Operator 记录人工准入；
8. Learner 看见结果和下一步；
9. 越权、旧链接和旧会话被拒绝。

退出：`AT-P0-301..309` 逐步有真人证据；0 个 Sev-1/2；每个支持介入均记录原因，不能把研发现场指导计为无协助通过。

### P0-4｜受控正式使用与 7 日观察（0.5 天切换 + 7 天观察）

用户结果：小范围新人可从 `journey.muchenai.com` 使用；故障时运营能在 10 分钟内进入维护或回退。

施工：

- 固定已通过 P0-3 的候选与 Journey V3；
- 备份与只读恢复摘要核对；
- 生产 Operator/Reviewer 登录、邀请、公开页面与 canonical URL 验证；
- maintenance/live 单次演练；
- 每日记录进入成功率、材料打开失败、支持介入、提交/评审周转、Sev 缺陷；
- 每日只允许一个 P0 blocker 修复 WIP，修复必须先在 staging 复现并走关键浏览器回归。

退出 `P0_LIVE_CONTROLLED`：连续 7 天无 Sev-1/2、状态冲突/重复事实为 0、核心闭环成功、维护/回退可执行。完整 production GO 的延期项仍保持真实状态。

## 4. P1｜可持续运营与体验优化

P1 只从真实一周使用数据进入，不凭想象排功能。

### P1-1｜内容运营工作台

- 结构化维护材料、任务要求、预计时长、负责人和链接健康；
- 草稿 → 预览 → Operator 发布不可变版本；
- 发布前展示 Learner 真实预览和差异；
- 不做通用 CMS、富文本平台或附件系统。

退出：内容负责人不依赖研发可完成一次新版本发布，旧 Enrollment 不漂移。

### P1-2｜运营队列与异常恢复

- 统一显示邀请、身份、待评、超时、修订和失败材料；
- 所有恢复使用有意图命令，显示影响范围和审计结果；
- 不提供通用状态编辑器。

退出：90% 日常异常无需研发/SQL；错误恢复不产生重复事实。

### P1-3｜Reviewer 工作效率与反馈质量

- 队列排序、固定提交版本、Rubric、修订模板和历史对比；
- Reviewer 校准样本与一致性记录；
- 反馈语言帮助 Learner 行动，不堆砌评分解释。

退出：90% 首次评审在 2 个工作日内；抽样反馈可执行且范围正确。

### P1-4｜产品观测与反馈闭环

- 事件：邀请打开、加入、材料打开/失败、开始、保存、提交、评审、修订、完成；
- 只采集最小 PII-free 运营指标；
- 每周按“用户阶段”而非服务模块复盘；
- 支持记录和页面反馈进入同一缺陷分类。

退出：能回答用户在哪一步流失、为什么介入、修复后是否改善。

### P1-5｜体验打磨

- 基于真实热区/观察优化信息层级、路线、动效和移动端；
- 保持 `/review`、`/ops`、`/content` 为专业工具界面；
- 通过可用性数据决定文案与视觉变化。

退出：当前行动理解率 ≥90%，支持介入率 ≤20%，无新的可访问性 blocker。

## 5. P2｜规模、韧性与能力扩展

P2 必须由明确业务量、风险或成本触发。

### P2-1｜多组织与规模

- 多 organization onboarding、scope 管理、隔离证明；
- 以真实目标负载重新定义 SLO，不沿用一次性合成数据替代产品验证；
- 批次、名册和 Reviewer 容量工具。

### P2-2｜通知与外部可观测

- 真实飞书通知接收人、回执、重驱；
- 外部日志、指标和告警演练；
- 通知失败继续不回滚业务事实。

### P2-3｜附件与内容介质

- 只有真实任务证明附件必要时才重开 WP-10；
- 私有存储、扫描、类型/大小限制、短时访问和删除/恢复门禁全部通过后启用。

### P2-4｜灾备故障域与完整 production GO

- 真实稳定运行 30 日后评审独立故障域；
- 异机恢复、RPO/RTO、外部观测、审批和观察窗口闭合；
- 明确从 `P0_LIVE_CONTROLLED` 升级为完整 production GO 的证据。

### P2-5｜更深的学习产品能力

- 仅根据真实反馈选择个性化路径、更多 Journey、导师协作或能力档案；
- AI 只能提供有来源的建议，不自动通过、淘汰或改变人事事实；
- 每项扩展重新建立用户问题、风险和最小纵向切片。

## 6. P0/P1/P2 总览

| 优先级 | 成功定义 | 核心工作 | 明确延后 |
| --- | --- | --- | --- |
| P0 | 真人能稳定完成探索营并受控使用 | 多角色身份、Learner 任务页、完整真人闭环、7 日观察 | 通用平台、附件、通知、跨故障域、多组织扩张 |
| P1 | 小范围运营不依赖研发，反馈能推动改进 | 内容发布、异常恢复、Reviewer 效率、产品观测、体验优化 | 企业级 GA、复杂自动化 |
| P2 | 经真实需求证明后安全扩展 | 多组织、容量、通知/观测、附件、灾备、进阶产品 | 无证据的预留式建设 |

## 7. 施工治理

- 单一产品 WIP；同一时刻最多一个会改变 auth、migration、Journey 或 release 的 PR；
- 每个 PR 必须引用一个 `AT-P*`，说明真人结果和非范围；
- 定向测试用于开发反馈，完整 gate 只在行为稳定后执行一次；
- 改 UI 必须有真实浏览器三视口和关键状态；改 auth 必须有真实 OAuth E2E；
- 不因 CI、provider 或 IaC 路径失败而自动扩大权限或重复部署；
- 同类问题第二次出现，先更新模型/合同和回归测试，再实现；
- 文档、代码、部署、业务发布、邀请和消息是独立动作，禁止默认捆绑授权。

## 8. 每日战情板

```text
当前唯一用户结果
当前 P0 blocker（进入/学习/提交/评审/修订/结果/运营/恢复）
真实复现证据
根因层级（内容/交互/身份/领域/运行）
今天唯一 WIP 与 Owner
验收 AT
是否需要发布/业务写入（默认否）
最新真人结果与支持介入
```

不报告提交数、测试数、文档数或部署次数作为产品进度。
